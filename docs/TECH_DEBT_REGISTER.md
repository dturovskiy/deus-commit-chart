# Prioritized technical debt, release gates and accepted risks

> Audited against `main` on 2026-10-11. This register is intentionally separate from the original **65-item remediation acceptance contract**: recording future work does not silently expand or mark the existing gates complete. Checkboxes track actual deliverables, with evidence required before closure.
>
> Priority definitions: **P0** blocks a trustworthy requested Marketplace handoff; **P1** is important residual product/security risk with a documented decision; **P2** is maintainability or optional quality improvement; **P3** is external or low-impact watch. `Accepted` means deliberately deferred with a specified boundary, *not* remediated.

## P0 — finish before publishing the next release

- [ ] **TD-01 — Verified next Marketplace version and install path.** Bump package metadata, lockfile, changelog, README badge/copy-paste examples and the manual remote-tag consumer to the *same new immutable version*; merge under PR-only Smoke; prove actual remote-tag installation in **both** local Git and real GitHub GraphQL modes; publish the GitHub Release and confirm Marketplace publishing/listing. The signed legacy `@v1` major alias is **not** the new release and still resolves to v1.4.1. Moving a signed existing tag requires a separately reviewed signing and compatibility path: **never force-push/delete/recreate it silently or replace it with an unsigned alias**. If that cannot be safely completed, keep the exact supported new version in the install example, flag the Marketplace button as outstanding, and do not claim that its `@v1` code was upgraded. **Evidence:** [v1.5.1 release](https://github.com/dturovskiy/deus-commit-chart/releases/tag/v1.5.1), [release policy](MARKETPLACE_RELEASE_POLICY.md). **Gate:** stable released tag + actual tagged-consumer result + checked Marketplace default/install snippet.
- [ ] **TD-02 — Final visual acceptance (DC-G3-08).** Human-review native README SVG plus generated HTML at 30/90/365 in both `github-compact` and `github-light` themes, desktop and narrow (~390px) viewport, including labels, chart bars, 7d trend, today-partial note, tooltip, focus and horizontal scroll. Follow the [complete human review sheet](VISUAL_QA_MATRIX.md). Take/screenshare evidence or a dated manual visual inspection note *and* verify existing contrast/Chromium CI. Do not replace actual legibility evaluation with DOM geometry alone. **Evidence to date:** [Chromium #38140764234](https://github.com/dturovskiy/deus-commit-chart/actions/runs/38140764234), `test/calendar-contract-mobile.test.js`. **Gate:** record actual reviewer outcome, devices, tested files and any fixes.
- [ ] **TD-03 — Release documentation and evidence sync.** Ensure the architecture disposition, security review, cache policy, operations runbook and all version examples agree with the merged PRs and latest production data. Historical run results must be explicitly dated rather than described as live latest. **Gate:** PR review plus tests for internal version and link consistency.

## P1 — explicit accepted risks, no unnecessary scheduled jobs

- [ ] **TD-04 — Publish-job write scope (DC-G2-10).** Current trusted-`main`, one-job `publish-pages.yml` has `contents: write` while fetching GraphQL, rendering and pushing to `activity-assets`. Checkout avoids persisting GitHub write credentials and the final publish step uses a temporary GitHub CLI credential helper, but the job-level write grant and fallback GraphQL token still exist. Smoke is read-only; full-SHA action pinning, independent verification and fast-forward-only push reduce but do **not** eliminate token exposure risk. Dedicated publish credential limited to the target branch or a second isolated write job would improve least privilege but would add jobs/credentials/complexity. **Recommendation: accept current design explicitly** until the operational risk justifies its cost; do not label a one-job design as strict least privilege. **Revisit if:** third-party build steps or dependencies appear, an incident occurs, the repository changes owners, or the user allows extra jobs/credentials. **Gate:** check permissions and document accountable sign-off and chosen trade-off; original checklist remains open until its wording/acceptance is resolved.
- [ ] **TD-05 — README cache observability (DC-G2-12).** GitHub controls raw/profile/camo and end-user/browser caches. Production manual checks repeatedly observed current SVG within ~20–56 seconds, including [three-sample audit #38146191299](https://github.com/dturovskiy/deus-commit-chart/actions/runs/38146191299): `24.38/40.21/55.63s` all `profile_raw_matched`, **zero observed stale-to-fresh transitions**, independent camo **not observed**. No cache invalidation upper bound or SLA can be inferred. Keep the **manual-only** probe with `samples=1|3`; no cache busting or automatic polling. **Revisit if:** user reports stale embeds, a real transition is observed or GitHub cache behavior changes. **Gate:** empirical transition or an explicitly recorded revised acceptance criterion that does not pretend a TTL was measured.
- [x] **TD-06 — Freshness reporting without alert spam (DC-G2-11).** Operational decision: on-demand diagnostics, selectable 8/24/48/72h thresholds, outcomes for fetch/integrity/freshness, CI stale/malformed rejection; no scheduled issue creation or separate alert job. Normal failed publisher Actions status remains visible. **Evidence:** [manual 8h run #38145526345](https://github.com/dturovskiy/deus-commit-chart/actions/runs/38145526345), [PR #24](https://github.com/dturovskiy/deus-commit-chart/pull/24).
- [ ] **TD-07 — Unprotected `main`.** Direct push could bypass PR-only CI. The maintainer deliberately postponed branch protection to avoid disrupting development. Keep PR + green CI as the release discipline; do **not** switch on protection without a new decision. **Revisit if:** additional maintainers get write access, unreviewed push becomes common, or a release regression escapes PR CI.
- [ ] **TD-08 — Historical private-activity metadata.** Four earlier `activity-assets/index.html` revisions stored private/restricted contribution-breakdown *metadata* (not a PAT); newer outputs use `daily-aggregates-only-v1`. No promise that public Git history, old artifacts, forks or caches can be erased. Never force-rewrite recovery history as routine cleanup. **Revisit if:** privacy requirements change or broader exposure is demonstrated. **Evidence:** [bounded history scan](REPO_HYGIENE_AND_SECRETS_AUDIT.md).
- [ ] **TD-09 — Consumer example timestamp-only publication noise.** The copy-paste consumer publisher correctly avoids byte-identical commits, but regenerated build timestamps can produce a commit without contribution changes; maintainer production publisher has a stricter identity/source-revision check. **Revisit if:** actual users report unwanted commit churn. **Gate:** tested zero-change semantic no-op in a separate backward-compatible PR; no need to delay the current release.

## P2 / P3 — keep visible, avoid premature refactoring

- [ ] **TD-10 (P2) — Pinned upstream Actions runtime generation.** `checkout` and `setup-node` are SHA pinned at reviewed v4.4.0, but GitHub may phase out the underlying older Node action runtime. Move to supported pinned major versions only with a compatibility PR and full Smoke. **Trigger:** official runtime deprecation notice or coordinated upgrade.
- [ ] **TD-11 (P2) — Browser renderer function serialization.** Pure rendering helpers are inlined via `Function.prototype.toString()` into standalone HTML. This shares mathematics between SVG and interactive output and passes source/parity/Chromium tests, but is brittle under future bundling/transpilation. **Trigger:** a build tool is added, function bodies change unexpectedly or parity CI fails; do not rewrite a working zero-dependency architecture preemptively.
- [ ] **TD-12 (P2) — Cross-browser device coverage.** CI proves actual Chromium desktop/390px interaction, keyboard and accessible labels, not exhaustive iOS Safari, Firefox or GitHub mobile-app rendering. **Trigger:** reported display issue or target audience requirement; TD-02's human visual pass is the immediate release gate.
- [ ] **TD-13 (P3) — Image cache outside publisher control.** Even after G2-12 is dispositioned, retain README embed caveat: raw and intermediary GitHub caches may lag independently and cannot be invalidated by committing a chart. No extra infrastructure should be deployed simply to chase an unsupported cache SLA.

## Release handoff invariants

- No new scheduled CI, monitoring or cache probes; no extra publishing job unless separately accepted.
- No direct changes to the signed historical `v1` or prior immutable tags.
- No forced rewrite of `main`, `activity-assets`, GitHub release history or private-history artifacts.
- Distinguish **GitHub contribution-calendar** counts from raw local Git commit counts and token-visible private-activity assumptions.
- Future additions to this register receive unique TD IDs with priority, risk, completion evidence and a reconsideration trigger. Keep the original 65 gates and this backlog as **two separate denominators**.
